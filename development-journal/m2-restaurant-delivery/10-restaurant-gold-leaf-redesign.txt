4A. PROMPT 2.7A DIAGNOSIS & REMEDIATION (NON-FUNCTIONAL THEME TOGGLE)
---------------------------------------------------------------------
- Root Causes Identified:
  1. Stacking Context & Click Interception:
     When an unauthenticated user loads the page, the authentication modal backdrop (.modal-backdrop.active) was fixed with inset: 0 and z-index: 1000. The top header (.top-header) had z-index: 90. Although #btn-theme-toggle was visible through the translucent backdrop, all click pointer events were absorbed by .modal-backdrop, preventing clicks from reaching #btn-theme-toggle.
  2. Double-Binding & Immediate Cancellation:
     frontend/shared/js/theme.js registered a DOMContentLoaded listener that bound click handlers to .theme-toggle-btn. Concurrently, frontend/restaurant/js/app.js registered its own click listener on #btn-theme-toggle. When clicked, both listeners executed in the same tick: listener 1 switched dark -> light, and listener 2 immediately switched light -> dark, producing no net change.
  3. Desynchronized Profile View Theme Options:
     The 3-button theme option group in Profile settings (Light / Dark / System) did not listen to the global 'zaykaa:theme-change' custom event, causing Profile settings to fall out of sync when toggled via the header button.
- Remediation Implemented:
  1. Top Header & Sidebar Elevation: Elevated .top-header (and .delivery-header) to z-index: 1001, and mobile sidebar to z-index: 1005. Both the header and mobile drawer now cleanly overlay modals, ensuring theme controls remain interactive on the login screen.
  2. Integrated Modal Theme Toggle: Added .theme-toggle-btn inside #auth-modal's header in both Restaurant and Delivery portals for immediate in-modal theme toggling.
  3. Idempotent Binding Guard: Added bindThemeToggleButtons() with a data-theme-bound guard in frontend/shared/js/theme.js to guarantee each button is bound at most once. Removed redundant listeners in app.js.
  4. Real-time Profile Synchronization: Added a 'zaykaa:theme-change' listener in profile.js (both portals) to keep the active state of Light/Dark/System buttons in lockstep with the header toggle.
