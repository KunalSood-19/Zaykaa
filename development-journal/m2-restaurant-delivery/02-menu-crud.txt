2. HOW IT WORKS
- Client requests -> Express restaurantRouter delegates to nested menuRouter (mergeParams: true).
- POST /:id/menu: Verifies caller owns restaurant -> validates payload -> saves with item_<uuid>.
- GET /:id/menu: Publicly queries menus.json for all items where item.restaurantId === :id.
- PUT & PATCH /:id/menu/:itemId: Confirms ownership and item membership -> updates fields/availability.
- DELETE /:id/menu/:itemId: Validates ownership and item membership -> removes item from menus.json.

3. TECHNOLOGIES & CONCEPTS
- Nested Routers with mergeParams: Preserves :id from parent path in child menu router handlers.
- Integer Paise Pricing: Prevents floating-point rounding errors in financial transactions.
- Dual-Level Resource Authorization: Verifies caller owns the restaurant AND the item belongs to it,
  preventing cross-restaurant URL manipulation.
- Referential Integrity Notice: CE-1 JSON storage lacks cascade delete; restaurant deletion can orphan
  menu items, which will be addressed in database migrations (CE-2).

6. VIVA QUESTIONS & ANSWERS
Q1: Why store food item prices in integer paise rather than decimal rupees?
A1: Floating-point numbers in JavaScript suffer from IEEE 754 precision issues (e.g. 0.1 + 0.2 !== 0.3).
    Storing monetary values in integer paise guarantees exact calculations during checkout.
Q2: What is the purpose of mergeParams: true in Express nested routers?
A2: By default, child routers cannot access parameters declared in parent routers. Setting
    mergeParams: true ensures req.params.id from /api/restaurants/:id is accessible in menu handlers.
Q3: How are cross-restaurant menu modifications prevented?
A3: MenuService loads the target item and verifies item.restaurantId === restaurantId. If they mismatch,
    it returns 404 Not Found, preventing an owner from updating another restaurant's item via their URL.
Q4: What happens to menu items when a restaurant is deleted in CE-1?
A4: Because flat JSON storage has no cascade delete or foreign keys, menu items remain orphaned.
    In CE-2, this will be handled via MongoDB middleware or database-level cascade triggers.
