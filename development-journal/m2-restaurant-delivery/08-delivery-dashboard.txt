6. VIVA QUESTIONS & ANSWERS
Q1: Why can a delivery partner not switch availability to 'Online' while an order is active?
A1: The platform prevents couriers from taking concurrent deliveries to ensure timely customer handovers and prevent
    conflicting routes. The backend enforces error code ACTIVE_ORDER_RESTRICTION if attempted.
Q2: How does the delivery dashboard handle competing couriers claiming the same available order?
A2: Order claims via PATCH /api/partners/orders/:id/accept are serialized atomically. If another courier claims first,
    the backend returns HTTP 409 CONFLICT, which the UI catches to display a notification and refresh the available pool.
Q3: How does the active delivery lifecycle enforce valid order progression?
A3: The dashboard disables pickup until the restaurant marks the order 'Ready for Pickup'. It then guides the partner
    step-by-step: Confirm Pickup (Picked Up) -> Depart (Out for Delivery) -> Confirm Handover (Delivered).
Q4: What happens to the partner profile state once an order is marked 'Delivered'?
A4: The backend atomically clears activeOrderId to null, increments totalDeliveries by 1, and restores isAvailable to true.
