2. HOW IT WORKS
- Modular Architecture: Separates shared utilities, authentication state, API client, and distinct view managers.

- XSS Prevention: All dynamic text interpolation passes through escapeHtml() to eliminate script injection vulnerabilities.
- Role Enforcement: Client-side role checking guards access while backend RBAC middleware protects all mutating endpoints.

6. VIVA QUESTIONS & ANSWERS
Q1: Why must the frontend convert prices from decimal Rupees to integer paise before sending to the backend?
A1: JavaScript IEEE 754 floating-point arithmetic causes precision rounding errors with currency. The platform contract
    mandates integer paise across all storage and API layers to ensure monetary consistency.
Q2: How does the dashboard prevent Cross-Site Scripting (XSS) when rendering customer and dish names?
A2: All dynamic user-supplied strings pass through `escapeHtml()`, converting `<`, `>`, `&`, `"`, and `'` into HTML entities
    before inserting into innerHTML.
Q3: How are dashboard metrics kept accurate without hardcoding or duplicate calculations?
A3: Metrics are derived directly from the loaded orders array. Revenue only counts orders with status 'Delivered',
    summing integer totals and formatting with `formatPaise()`.
Q4: What happens if a restaurant owner's JWT token expires while interacting with the dashboard?
A4: The `apiClient` catches HTTP 401, clears localStorage session data, emits `zaykaa:session-expired`, displays an error toast,
    and opens the authentication modal prompting the user to re-authenticate seamlessly.
