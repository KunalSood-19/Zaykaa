2. HOW IT WORKS
- Cart Addition: Clicking `+ ADD` on any available menu item checks if the cart is empty or belongs to the current restaurant. If matching, the item is added and stored in `localStorage`.
- Conflict Handling: If an item belongs to a different restaurant, a warning modal prompts: "Your cart already contains items from [Restaurant A]. Discard them to add from [Restaurant B]?" Users can cancel or discard and switch.
- Cart Drawer: Opening the drawer displays item details, unit price, quantity steppers (1-20), line totals, and full bill breakdown (Subtotal + ₹40 Delivery Fee + 5% GST = Grand Total).
- Checkout Flow: Clicking "Proceed to Checkout" opens the checkout dialog, automatically pre-filling the customer's default delivery address (`cust_8829`).
- Backend Order Creation: Submitting the order sends a `POST /api/orders` payload containing only item IDs, quantities, restaurant ID, and delivery address. The backend serves as the single source of truth for all pricing, taxes, availability checks, and status assignment (`Placed`).
- Post-Order: On receiving HTTP 201 with `{ success: true, data: order }`, the cart is emptied from browser storage, modals are dismissed, and the Order Confirmation modal displays the canonical order details.

3. TECHNOLOGIES & CONCEPTS
- Client-Side State Management: Pure vanilla JS event-driven cart engine (`cart.js`) exposing listeners via Pub/Sub callbacks (`cart.subscribe()`).
- Single Source of Truth Architecture: Client computes indicative totals for immediate user feedback, but never passes price or total fields to `POST /api/orders`; the server authoritatively recalculates all line items, tax, and delivery fee.
- Defensive Form UX: Disables submit button during active `fetch` requests and displays an animated spinner to prevent duplicate order submissions.
- Browser Persistence: Uses `localStorage` safely without sensitive data (storing only `restaurantId`, `restaurantName`, and `{ id, name, price, quantity, isVeg }`).
- Responsive Slide-over Drawer: Pure CSS animations (`transform: translateX(0)`, backdrop filters, glassmorphic headers) without third-party UI libraries.

6. VIVA QUESTIONS & ANSWERS
Q1: Why should client-side cart totals never be trusted by the backend when placing an order?
A1: Client-side storage and network payloads can be easily tampered with using browser dev tools or proxies. If the client sent `totalAmount`, a malicious user could modify a ₹1,000 order to ₹1. The backend must always look up current item prices from its authoritative database or JSON repository, verify item availability, calculate subtotal, taxes, delivery fee, and enforce single-restaurant constraints.

Q2: How does Zaykaa prevent ordering from multiple restaurants in a single cart?
A2: Each cart holds a `restaurantId`. When a user attempts to add an item from a different restaurant, `cart.js` detects the mismatch and triggers a conflict modal. The user must explicitly choose to either discard the existing cart to switch restaurants or keep the current items and cancel the addition.

Q3: How does the checkout form prevent accidental duplicate orders on slow network connections?
A3: On form submission, the submit button is immediately disabled (`disabled = true`), its text changes to "Placing Order...", and a loading spinner is displayed. Once the backend responds or if a validation error occurs, the state is restored. This prevents rapid double-clicking from triggering multiple `POST /api/orders` calls.
