2. HOW IT WORKS
- Flow: Client HTTP Request -> identity.middleware parses `x-customer-id` -> Router -> Controller -> Service -> Repository -> `backend/data/*.json`.
- Order Placement: Server fetches authentic item prices from `menus.json`, calculates subtotal, tax (5%), and delivery fee (₹40), rejecting client-side price tampering. Sets initial status `Placed`.
- Access Control: `GET /api/orders/:id` and cancellation require `order.customerId === req.user.id`.
- Cancellation Guard: Only orders with status `Placed` or `Accepted` can be cancelled. `Preparing` or terminal statuses return 400 `ORDER_CANNOT_BE_CANCELLED`.
- JSON Persistence: `jsonStorage.js` uses atomic writes (write to temp file then rename) and sequential promise queues per file to prevent corruption and race conditions.

3. TECHNOLOGIES & CONCEPTS
- Node.js (v24): Native ES Modules (`import`/`export`), native `node:test` and `node:assert`, and native `fetch`.
- Express.js (v5): Modular routing, body parsing, static asset mounting, and centralized 4-parameter error middleware.
- Repository Pattern: Decouples business services from storage; in Phase CE-2, only `*.repository.js` files need swapping to Mongoose.
- Atomic File Operations: Writing to a `.tmp` file and renaming via `fs.rename` guarantees that partially written files never corrupt data.
- Defense in Depth: Client-supplied prices and totals are completely ignored; the backend authoritatively recalculates all financial totals.

6. VIVA QUESTIONS & ANSWERS
Q1: Why must order pricing and total calculation happen strictly on the backend?
A1: Client-side prices can easily be tampered with via browser DevTools or curl. The server must authoritatively query menu prices, verify item availability, and compute subtotal, taxes, and delivery fees.
Q2: How does the Repository Pattern support migration from JSON files to MongoDB in CE-2?
A2: By exposing standard async methods (findById, findAll, create, update, delete) returning POJOs, controllers and services remain completely decoupled from the storage layer. In CE-2, only repository files are replaced with Mongoose models.
Q3: Why are atomic writes necessary when persisting data to JSON files?
A3: Direct writes can leave corrupt or empty files if the server crashes or power fails mid-write. Atomic writes first write data to a unique temporary file and then rename it, an atomic filesystem operation.
Q4: What rule prevents customers from cancelling food orders once cooking begins?
A4: The order state machine checks that status is `Placed` or `Accepted`. Once the restaurant changes status to `Preparing`, cancellation is rejected with `400 Bad Request` (code `ORDER_CANNOT_BE_CANCELLED`).
