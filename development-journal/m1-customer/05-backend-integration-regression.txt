6. VIVA QUESTIONS & ANSWERS
Q1: Why is test concurrency set to 1 when testing file-based JSON repositories?
A1: File-based persistence involves disk I/O operations on shared JSON files (e.g., `orders.json`). Running test files concurrently in separate threads can cause race conditions where one test's teardown overwrites another test's active data. Setting `--test-concurrency=1` ensures sequential execution with clean snapshot isolation.

Q2: How does Zaykaa handle duplicate items submitted in the same order payload?
A2: In `order.service.js`, the server iterates through requested items and checks if the item already exists in the canonical line items list. If present, it consolidates them by summing the quantities, while verifying that the total quantity for that dish does not exceed the allowed maximum of 20.

Q3: What guarantees that production users will not see sensitive internal stack traces on errors?
A3: The centralized error handling middleware in `app.js` checks `process.env.NODE_ENV === 'development'`. In production environments, internal stack traces are stripped, and only the standardized error envelope with a machine-readable `code` and human-friendly `message` is returned.
